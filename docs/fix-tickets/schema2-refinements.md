# schema 2 统一世界体系的后续修正（2026-10-14）

## 背景

GPT 在 2026-10-14 完成了工单 24/20 的统一世界体系（schema 2）重构，提交 `7a7858a`。
整体质量不错，860 个后端测试和 105 个前端测试全部通过。但有几处会在实际使用时卡住的问题，
以及文档和规范没有完全跟上。

## 已修复的问题

### P1-1：场景条件与世界属性同名时无法开演
- **现象**：`SceneEngine.__init__` 发现 `initial_conditions` 与任一世界事实的属性名或标签相同，就直接抛错。
  场景被置为 paused，而后端没有修改场景的接口，这个场景就再也无法开演。
- **最容易撞上的入口**：
  - 导演规划时写了"季节""天气"这类常见键；
  - 分叉表单里的 IF 条件会进入 `initial_conditions`，用户填"季节=夏"就会卡住新分支的首场。
- **修复**：改成警告并移除冲突条目，而不是抛错。移除的内容走世界状态获得，不影响场景本意。
- **位置**：`backend/scene_engine/engine.py:138-157`

### P1-2：迁移后从旧快照分叉会丢失物件规则
- **现象**：旧快照没有 `world_revision_id`，分叉时会创建空世界版本。`initialize_branch_world` 
  没有传 `definitions`，新分支连物件规则都没有，无法裁决。
- **影响**：迁移时选中的事实只有走"下一场"才能继承；continue、回滚、分叉都会丢。
- **修复**：分叉旧快照时同时传入项目定义（`await repository.list_objects(project_id)`），
  让新分支能从迁移基线继承事实，也有物件规则可用。
- **位置**：`backend/services/orchestrator.py:1311-1316`

### P2-3：裁决器看不到世界层事实
- **现象**：`adjudicate_world` 的 payload 只有目标物件状态，看不到"宫门封锁中"这类世界事实。
- **影响**：裁决时无法判断"城门已封，出城失败"这类依赖世界层的可行性。
- **修复**：新增 `world_facts` 字段，包含所有 global 可见性的世界层事实。
  只给 global 的，hidden 和 observable 的不进裁决器。
- **位置**：`backend/agents/environment_agent.py` 的 `adjudicate_world` 方法和 `_UNIFIED_PROMPT`

### P2-5：评估 prompt 改写用字符串切片
- **现象**：用 `prompt.index("- world_state_delta")` 和 `prompt.index("- 结局判定")` 截取。
  以后只要有人改了措辞，新项目的每一场评估都会抛 `ValueError`。
- **修复**：改用 HTML 注释标记 `<!-- WORLD_DELTA_SECTION -->`，并加 try/except 和双重检查。
- **位置**：`backend/agents/director_agent.py:526-544`

### 文档同步

## 仍待处理的问题

按严重程度：

### P2-4：导演仍能把秘密写成全员可见的事实
- **现象**：导演的 `world_operations` 只靠 prompt 约束和形状校验（只许 world 层、只许 global）。
  换个写法仍然能把"王后已知诺安对账页敏感"这样的认知事实变成 global。
- **影响**：提案在"下一场"时自动提交，界面只读展示，不能逐条确认；AutoPilot 下更是无人查看。
- **建议**：需要加用户确认界面，或者限制导演只能提出"哪些事实会变"，值由系统填。

### P3：其他已知边界（可排期）
6. 同分支已有场景在跑时，再点开演会直接把 pending 场景置为 paused（与陷阱 8 定义不符）
7. 每次裁决前都检索记忆（一次 embedding 调用），但只有触发揭示时才用得上
8. 每个世界版本存完整副本，不做回收（文档已注明，存储会持续增长）
9. 地点按 `Scene.location` 自由文本匹配（文档已注明）
10. `world_access` 引用了 orchestrator 的私有函数 `_branch_lock`（分层上不太干净）

### 缺失的目标
- **定向通告（分区 C）**：用户命令可以指定哪些角色知情，但导演的提案只能写全员可见的事实。
  这是你最初目标 1"异步信息渠道"里"只通知某些人"那一半。
- **场景结束结算（方案三）**：由环境层统管世界状态，导演只管叙事。没有做。

### 规范和风格
- 提交信息是英文，不符合 Conventional Commits（违反 §10.3）
- 新代码的注释和 docstring 是英文（§10.4 要求中文）
- engine.py 里有不少一行写多条语句的地方，和周围代码不一致

### 文档
- `docs/fix-tickets/` 完全没动：24-20 设计单里 PR-2b、PR-3 的状态，NOTES 里这次的设计决策，
  README 索引，都没有更新。按"工单保留目的"的原则，至少要写明 2b、3 已被这次实现取代，
  以及哪些目的还没完成。
