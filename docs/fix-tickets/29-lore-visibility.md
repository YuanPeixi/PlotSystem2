# 工单29：世界设定（lore）的可见性泄露

**优先级**：P1（破契约1，且所有已建项目都受影响）
**依赖**：无
**后续**：24（物件表）的"隐藏规则"抽取沿用本单的可见性判定，必须先合本单

---

## 1. 现象

种子文本里只有部分角色知道的秘密，构建后进了**每个角色**的 system prompt。

实测项目《玻璃王冠》：世界设定共 8 条，**全部**是 `scope=global`，被原样复制进 5 张角色卡。
其中包括"王后知道伊莎贝尔并非国王亲生""粮仓短缺是王后安排的""玻璃王冠读取佩戴者记忆"——
种子原文明确写了伊莎贝尔、诺安、王后各自不知道其中哪几条。角色按关键词挑设定
（`CharacterAgent._select_lore`，命中 +5 分、取前 6 条），场景里一出现"王冠""王后"，
这些秘密就进了伊莎贝尔的 prompt。

成因有两层：

- **抽取侧**：`WorldRulesExtractor` 的提示词只给了 `"scope": "global"` 一种示例，
  抽取时既不知道有哪些角色，也拿不到角色 ID，实际上无法产出私有条目；
- **分发侧**：`run_graphrag` 把所有 global 条目复制进每张角色卡。

## 2. 为什么必须修

- 信息不对称是本项目区别于群聊模拟的核心（CLAUDE.md §1.4），这个泄露在构建那一刻就把它抹掉了；
- **静默**：角色照常演，LLM 有时还会"装作不知道"，从输出上看不出来；
- **不会自愈**：设定是复制进角色卡的，修了构建代码，已有项目的卡片仍然带着全部秘密；
- 工单 24 / 20 的物件"隐藏规则"如果走同一条通道，环境层做得再好，角色也早就知道答案。

## 3. 判据（DoD）

1. 构建产出的每条设定都有明确可见性：**公开**（进全部角色卡）/ **私有**（只进知情角色的卡）/
   **隐藏**（不进任何角色卡）；
2. **失败即收紧**：分类调用失败、条目漏判、可见性取值非法、知情者名字对不上任何角色时，
   该条不发给任何角色（只 warning），绝不退回 global；
3. 读取侧只认 `global` 与**完全等于** `character:{本角色 id}` 的 scope，其余一律不注入；
4. 已有项目有一条修复路径，默认只预览不写入，写入前备份旧设定；
5. 用《玻璃王冠》这类"秘密分属不同角色"的种子构造回归用例，验证秘密不进不知情角色的 system prompt。

## 4. 红线与已排除

- **不得退回 global 兜底**。漏掉一条公开设定，角色只是少知道一点背景；泄露一条秘密，
  这场戏的信息差就没了，而且无痕。两者代价不对称，所以一切不确定都按"不发"处理。
- **不改 `LoreEntry` 模型**。多人知情的私有设定按知情者各发一份 `character:{id}` 副本，
  卡片本来就是每人一份拷贝，不需要新字段，也就不走 §5.4 的三步 checklist。
- **已排除：抽取时一并判可见性（一次调用）**。迁移已有项目时只有现成条目、没有抽取过程，
  需要单独的判定；两条路径各写一份判定逻辑迟早会漂移。故构建与迁移共用同一个分类器，
  构建多花一次调用。
- **已排除：用字面重叠判断"公开条目是否撞上某人的未知事实"**。公开事实与秘密常共用词
  （"北境缺粮"与"缺粮是人为的"），误判率太高；证据直接交给分类器：每个角色的已知 / 未知事实。
- **已排除：给隐藏设定建项目级存储**。目前没有任何导演侧代码读设定，建了也是死存储；
  导演看的是角色卡的 `unknown_facts`。工单 24 引入导演 / 环境侧的设定存储时再说。
  迁移脚本把被移除的条目写进备份文件，不会丢。
- **已排除：迁移做成 API**。这是一次性修复，脚本足够；前端入口等工单 05 做设定编辑时再考虑。
- 分类器的 prompt 含全体角色的 `unknown_facts`。它属于构建期、面向导演的生成过程，
  与 `PersonaBuilder` 同级，不进任何角色可见的上下文（契约1 的条文同步补上这一处）。

## 5. 验收

- 分类器的每条失败路径（调用抛错、漏判、非法取值、知情者名字全对不上、index 为 bool）
  都要有用例，并断言**不发给任何角色**，而不只是"没抛异常"；
- 端到端用例要走真实的 `run_graphrag` 分发 + `CharacterAgent.build_system_prompt`，
  场景上下文里必须含能命中秘密关键词的词（否则 `_select_lore` 本来就不会选中它，是假通过）；
- 迁移用例要覆盖：预览模式不写卡片；写入模式有备份、私有条目只留在知情者卡上、
  已经是 `character:` 的条目原样保留。
