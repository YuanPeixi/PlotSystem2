# 工单30：角色回复的输出边界（续写剧本 / 伪造环境结果 / 空回复）

**优先级**：P1 ｜ **依赖**：20 PR-2a ✅（放大因素在那里落地，修复不依赖它） ｜
**契约影响**：契约 1 / 3 / 7，陷阱 9 / 14 / 24 / 27

> owner 决策**：30c 用哪套 prompt 方案，按 30b 的数据定。排期理由见 [NOTES.md#t30](./NOTES.md#t30)。

## 1. 现象

2026-10-09 烟测 PR-2a（`ENVIRONMENT_MODE=adjudicate`，角色模型 OpenRouter `deepseek/DeepSeek-V4-Flash`）。

**续写剧本**：角色说完自己的台词后不停，把"目前对话"当剧本往下写 —— 替其他角色写台词
（`阿德里安: …`）、写 `【环境】…` / `【旁白】…`，最后复读一个自造标签（`【导演视角】（可公开给用户，
但不可直接注入角色提示词）` × 几十遍）直到输出上限。整段被解析进 `dialogue`：

| 场景 | 轮次 | 对白长度 | 内容 |
|---|---|---|---|
| `1198aeb6` | 11 塞芙拉 | 1478 字 | 替阿德里安、自己续写台词，两段 `【环境】`、一段 `【旁白】` |
| `149ff4bd` | 5 阿德里安 | 1308 字（导出原文 3866 字） | `【用户】 【环境】…底座内侧，确实藏着一片极薄的夹层。` + 复读 |

全库统计：有环境回合的这两场各 2 轮被污染、最长对白 1300+ 字；此前 13 场（无环境回合）
最长 260 字，只有一处轻微的自带名字前缀（`57c43e9b` 第 12 轮"塞芙拉: …"）——**隐患早于环境层存在，
环境回合把它放大了**。

**空回复**：`57c43e9b` 第 13、14 轮、`2efe3a11` 第 10 轮、`149ff4bd` 第 13 轮的对白、动作、独白三项全空。
计数显示调用成功（`failures=0`）：服务商返回了空 `content`，`utils/llm.py` 以 `content or ""`
当成功交回，引擎落成一个空轮次。没有记 `finish_reason`，分不清是推理耗尽额度还是上游故障。

### 根因（2026-10-09 分析）

1. **任务形态就是"续写剧本"，而 prompt 没有输出边界**：user 消息是一份 `名字: …` 逐行排列的剧本
   加一句"现在轮到你发言"，格式规范只说回应里要有什么，从没说"只写你这一轮"；角色调用不设
   `max_tokens`、没有 stop。
2. **环境回合引入了"无名、谁都能写"的行**：`【环境】叙述` 与 prompt 的区块标题（`【目前对话】`
   `【当前环境】` `【你此刻想起的】`）同形 —— 模型学到"`【X】` 是我可以输出的标签"，于是自造了
   `【用户】` `【旁白】` `【导演视角】`。以前冒充别人至少要写出别人的名字。
3. **R7 的措辞在暗示"环境会紧接着回应"**："成不成、发生了什么由环境告诉你"，加上记录里反复出现的
   "碰王冠 → `【环境】…毫无动静`"配对，模型把配对补完了。字面上它守住了 R7（`*动作*` 里只写尝试），
   结果写进了对白。
4. **放大回路**：被污染的对白是公开的，进全场 transcript 与长期记忆；`149ff4bd` 是 `1198aeb6`
   的下一场，上一场的假台词很可能经记忆检索回到 prompt，成了"台词里夹 `【环境】`"的范例
   （`memory_context_used` 未落盘，无法直接证实）。【你此刻想起的】里的记忆本身就是原样剧本行，
   且紧挨着发言指令。没有长度上限，一旦进入续写模式就复读到服务商上限。

## 2. 为什么必须修

- **绕过裁决器伪造事实**：`149ff4bd` 第 5 轮写出"底座内侧确实藏着夹层"，真实的环境回合（第 6、7 轮）
  裁决的是"毫无动静"。伪造的那句作为公开对白进了全体在场角色的长期记忆 —— 长期记忆按正文寻址、
  **不随回滚撤销**（陷阱 10），没有任何清理路径。环境层的意义（以隐藏规则为准的一致裁决）被架空。
- **冒充他人**：替别的角色写的台词同样进全场记忆，等于凭空给别人安了一句没说过的话。
- **静默**：没有日志、没有前端提示；空回复同样静默落库。
- **成本**：复读到上限的一轮按输出上限计费。
- PR-2b（物件状态跨场）与 PR-3（整场验收）都建在这上面：前者让伪造结果走得更远，
  后者的"扫描秘密"会被伪造内容干扰。

## 3. 判据（Definition of Done）

### 3.1 PR-30a：兜底（确定性，与档位无关）

- **截断续写**：角色回复在解析（独白 / 动作 / 对白拆分）**之前**按"续写标记"截断，截掉的部分
  不进 `dialogue` / `action` / `inner_thought`，因而不进 transcript、记忆、事件摘要与意图抽取。
  续写标记至少覆盖：`【任意】` 标签；本场**其他**参演角色名后跟半角或全角冒号。
  两种位置都要处理：另起一行的，与同一行内紧跟在正文之后的（§1 的两例落库后已被塌成空格，
  拿不到原始换行，用例两种都要钉）。
- **自带本人名字前缀**（`塞芙拉: 诺安大人…`）剥掉前缀、保留正文，不算续写。
- 截断**可观测**：至少一条 warning，带场景、角色、轮次、截掉的长度与开头一小段。
  要不要在轮次上留标记给前端看，由执行者定；加字段就走 CLAUDE.md §5.4 三步。
- **角色调用设输出上限**，新增配置项（进 `.env.example`）。**先在实际角色模型上量**：
  若服务商把推理 token 计入 `max_tokens`，上限过低会把正常回复截成空 `content` —— 正好制造出
  本单要修的另一个现象。
- **空 `content` 不是成功**：`utils/llm.py` 把空白 `content` 当作可重试的失败（走既有的 3 次退避，
  计入工单25 的重试计数），日志带 `finish_reason`。重试耗尽按既有的 `LLMError` 语义处理
  （角色轮次上即整场转 `paused`，可续跑）。这条对所有 `purpose` 生效 —— 任何用途的空回复都不合法。
- 截断后什么都不剩（整段回复就是续写）按空回复处理，**不得落一个空轮次**。

### 3.2 PR-30b：回放评测脚本（只读，调 LLM）

`scripts/` 下新增脚本：从库里取出指定场景、指定轮次之前的现场，按若干 prompt 变体各生成 N 次，
输出每个变体的**污染率**（用 30a 的同一个检测函数判定，不另写一套）、截断前长度分布、空回复率，
并把各变体的样本并排导出供人工读（演技好坏只能人看）。

- **基线变体必须调用真实的 `CharacterAgent` prompt 构建**，不得复制一份模板 —— 复制的基线
  会和真实代码漂移，比较就没有意义。候选变体可以是脚本内的原型。
- **记忆块无法原样复现**：`memory_context_used` 未落盘，现在检索又会拿到之后写入的（含已污染的）
  记忆。脚本要明确选一种口径（如统一空记忆块，或只检索时间戳早于该轮的条目）并在输出里写明；
  结论只在变体之间相对比较，不当绝对值。
- 默认先打印将发起的调用次数，确认后才跑（同 `reclassify_lore` 的预览口径）；计数走工单25 的计数器。
- 回放集至少包含 §1 的两个污染现场，另取几个正常现场看副作用（变体不该让正常回复变差、变短到失去戏剧性）。

### 3.3 PR-30c：prompt 改造（方案由 owner 按 30b 数据定）

候选（2026-10-09 讨论，细节见 [NOTES.md#t30](./NOTES.md#t30)）：

| 方案 | 做法 | 改动面 |
|---|---|---|
| A 规则 + 沉浸 | system 加输出边界（"只写你这一轮，不替他人 / 环境 / 旁白写，不输出【】标签"）+ 第一人称处境；R7 改成"结果你说完之后才会知道，不归你写" | 一个模板 |
| B 叙事化视图 | 角色看到的"目前对话"改成小说体：`名字：「台词」（动作）`，本人记作"你"；环境行改成不与区块标题、发言人行同形的感知句；记忆块转述成"你记得…" | 只改视图，存储不动 |
| C 多轮消息结构 | 本人过去的轮次作 `assistant`，他人与环境作 `user`，记忆 / 当前环境 / 发言指令在末条 `user` | `respond` 接口与预算裁剪 |

判据：
- 回放集上污染率显著低于基线（具体阈值 30b 出数后与 owner 定），空回复率不升；
- 人工抽读：正常现场的回复不变差；
- 改动对 off / record / adjudicate 哪些档位生效由 owner 定（根因与档位无关，倾向全局）。
  动 off / record 的 prompt 会让 PR-2a 的 golden 用例失效 —— **那是有意改，不是回归**，
  在 PR 说明里写明并整体更新，不要逐条"修绿"；
- 选 C 时一并评估对工单21（私有内心 OS）的影响：多轮结构里"先想再说、不入档"就是 assistant 前多一步。

## 4. 红线与已排除

**红线**

- **R1 存储格式不动**：`render_turn` 的输出是长期记忆的寻址键（陷阱 24），B / C 只能改角色看到的
  **视图**。改了它，续跑重放与既有记录对不上，去重失效。
- **R2 契约 3**：system 整场不变；对话只在末尾追加、不逐行滑窗；【当前环境】留在 user。
  C 方案的多条消息同样只追加，预算超限成块丢弃。
- **R3 契约 1**：本人的独白只给本人（C 方案里本人的 assistant 消息可带自己的独白）；他人的独白、
  环境回合的私密细节（只给 `perceived_by`）照旧不进任何别人的视图。
- **R4 截掉的内容不挽救**：不把截下的 `【环境】` 当提示、不改写成旁白、不交给裁决器。
  裁决只认隐藏规则（设计单 §3 "不做自动纠正"）。
- **R5 失败不伪造**（同陷阱 14 / 27）：空回复、整段被截光都不补"（沉默）"之类的占位台词。
- **R6 契约 7**：输出上限、空回复判定都在 `utils/llm.py` 这个唯一出口或其调用参数上做，
  不在别处新建客户端；新配置走 `settings`。

**已排除**

- **结构化输出（JSON / 字段化）**：边界问题能根治，但中文台词明显变成"填表"，温度 0.8 下 JSON
  出错率不低，`*动作*` / `[独白]` 格式与解析、记忆、前端深度绑定，迁移面最大，且 OpenRouter
  各服务商对 `json_object` 支持不一。将来若对物件动作走 function calling，只结构化动作部分。
- **环境叙述不进"目前对话"**：违反设计单 §5 / 陷阱 27（公开叙述要让全体在场者看见），旁观者
  会丢失"谁碰了什么、发生了什么"的时间线。B 方案把环境行改成不可模仿的形态即可。
- **只靠 stop 序列**：OpenAI 兼容接口通常最多 4 个，角色一多放不下；且同一行内的续写挡不住。
  可以作为 30a 的补充，不能代替事后截断。
- **只调参数**（降温度、加 `frequency_penalty`、换角色模型）：可以作为 30b 里的对照变体，
  但不能当修复 —— 换个模型或服务商就回来了。
- **事后清理已污染的数据**：分不清哪句是伪造的（伪造的环境结果与正常台词同在一个字段里）。
  本单不追溯；`check_memory_dupes` 式的只读统计可以有，清理不做。烟测用的分支 `4cffc056`
  已被污染，测 30c 时从污染之前的快照分叉。

## 5. 验收

- 30a：§1 的两个现场的原文（含复读尾巴）作为解析用例，截断后 `dialogue` 只剩本人台词；
  同一行内、另起一行两种位置各一例；正常台词里出现别的角色名（"诺安大人说得对"）**不被误截**
  （名字后不跟冒号）；空 `content` 用例断言发生了重试且没有落空轮次 —— mock 要让前两次返回空、
  第三次返回正文，**只返回一次空的话测不到重试**。
- 30b：脚本对基线变体复现出非零污染率（否则回放口径有问题，后面的比较全无意义）。
- 30c：在新分叉的分支上用 adjudicate 档整场跑《玻璃王冠》，`dialogue` 里不再出现 `【` 标签与他人
  台词；跑完用 `scripts/usage_report` 对比角色调用的输出 token。
