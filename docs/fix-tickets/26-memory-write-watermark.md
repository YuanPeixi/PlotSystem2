# 工单26：记忆写入点与固化水位线统一

**优先级**：P2 ｜ **依赖**：无 ｜ **契约影响**：契约 6（降级路径不得被破坏）

> 本单已按新骨架重写：只给目标、判据与红线，不给分步实现。
> 实现方案由执行者自行决定，但必须满足 §3 的全部判据、不越 §4 的红线。

## 1. 现象

`Scene.turns_consolidated` 是"哪些轮次已进过长期记忆"的水位线（`CLAUDE.md` §4.2 陷阱 9），
崩溃续跑时靠它决定重放哪一段。但**场景内的自动固化完全不推进它**：

`MemoryManager.add_experience` 在短期缓冲满（`SHORT_TERM_BUFFER_SIZE`，默认 40）时会自己
调 `consolidate()` 写进长期记忆，而 `Scene.turns_consolidated` 毫不知情。于是：
单次 `run()` 跑到第 40 轮 → 前 40 轮已入库但水位线仍是 0 → 第 45 轮崩溃 →
续跑重放 `turns[0:45]` → **前 40 轮第二次入库**。

**触发条件**：单次 `run()` 产生 ≥ `SHORT_TERM_BUFFER_SIZE` 轮且随后异常中断。
默认 `DEFAULT_MAX_TURNS = 20` 碰不到，但 `max_turns` 由 `DirectorAgent.plan_scene` 输出或
`CreateSceneRequest` 指定，**没有上限校验**，因此可达。

同族缺陷"水位线赋值等到 `run()` 返回才落库"已在 PR #15 修掉（`run()` 的 `on_persist` 钩子），
本单处理剩下这一处。

> `continue` 续跑不受影响：进来时 `turns_consolidated == len(turns)`，重放循环为空，
> 且每次 `run()` 的缓冲从空开始，单次只加约 6 轮。

## 2. 为什么必须修（而不是"概率低，先放着"）

长期记忆按角色+分支隔离，但**不随分支回滚**（`CLAUDE.md` §4.2 陷阱 10）：

- 重复只会累积，不会自愈，也没有任何现存路径能清理；
- 检索是 `top_k`，同一句台词占掉两个坑，**污染的是检索质量，不只是磁盘**；
- 全程静默，没有任何日志会提示"这条写过了"。

工单 09（记忆检索质量）必须排在本单之后，否则是在脏数据上做评估。

## 3. 判据（Definition of Done）

### 3.1 主线：写入长期记忆与推进水位线必须是原子的一对

- **场景内的固化时机由引擎掌握**，不再由某个角色的缓冲状态自发触发。
  触发权在引擎的理由见 §4「已排除」第 1 条。
- 每次固化后，`Scene.turns_consolidated` 必须推进到当时的轮次，
  **并在同一次落盘内写库**（走 `on_persist`，理由见 §4 红线 R1）。
- 固化周期可配置（新增配置项，建议默认为 `SHORT_TERM_BUFFER_SIZE` 的一半左右）。
- 场景正常结束时的那次固化行为不变。
- 崩溃续跑时，`dialogue_log[turns_consolidated:]` 的重放机制必须继续有效 ——
  **不能把"该补的补不回来"一起改没了**（见 §5 的既有用例）。

### 3.2 兜底：长期记忆写入本身幂等

即使 3.1 做完，未来每新增一个写入点（世界变量写回、环境智能体裁决落档、动态图谱写回）
都得记得维护水位线。靠"每个人都记得"维持不住，因此需要一层与水位线无关的幂等兜底：
**同一角色写入同一段文本两次，检索结果只应有一条。**

必须一并确认：

1. **降级路径（`_collection is None` 时的内存 fallback）行为一致** —— 否则契约 6 的
   两条路径会分叉；
2. 所选方案在当前 chromadb 版本上可用；
3. 幂等是否会导致 embedding 被重复计费/调用，若会则需前置判断。

**已知副作用（需明确接受并在代码里留一行注释）**：同一角色在不同场次说出**完全相同**的
一句话会被合并成一条。工单 15 已做过"同句去重"，方向一致。

### 3.3 历史数据：只评估，不清理

现网 `data/projects/*/chroma_db/` 里可能已有重复条目。提供一个**只读**脚本
（`scripts/check_memory_dupes.py`）按集合统计完全相同文本的出现次数、输出 Top N，
供人工判断。脚本注释里写明：确认重复严重时最干净的处理是删掉 `chroma_db/` 重跑
（长期记忆可从 `dialogue_log` 重建，不是唯一真相源）。

## 4. 红线与已排除

**红线**

| 编号 | 约束 | 理由 |
|---|---|---|
| R1 | 水位线推进**不得**放在 `on_turn` 之后 | `on_turn` 会推 SSE，而落盘必须先于推送（工单 23 的既有约定）。用不推事件的 `on_persist` |
| R2 | 契约 6：Chroma 缺失时的降级路径必须与正常路径同语义 | 离线/CI 必须能跑通 |
| R3 | 不得自动清理历史重复数据 | 不可逆，且无法区分"重复写入"与"角色确实说了两遍" |
| R4 | 不得顺手改 `SHORT_TERM_BUFFER_SIZE` 默认值 | 缓冲容量与固化周期是两件事；3.1 之后缓冲只负责"最近上下文" |

**已排除的方案**

1. **让 `add_experience` 把固化条数回报给引擎** —— 记忆按**条**计数（每轮 × 每个在场角色），
   引擎按**轮**计数，两者不是 1:1；且各角色缓冲在 `prime()` 回填后深浅不一，
   会各自在不同轮次触发。把触发权收归引擎才能保证全场同步。
2. **给长期记忆加分支维度** —— 归工单 08，已完成，与本单正交。
3. **给 `max_turns` 加上限校验** —— 可以顺手加，但不是本单的必要条件；
   3.1 之后超长场景本身已安全。

## 5. 验收

| 用例 | 断言 |
|------|------|
| 周期固化推进水位线 | 跑一场轮数超过固化周期的场景，断言中途落盘被触发，且每次落盘时 `turns_consolidated` 等于当时的轮次 |
| 中途固化后崩溃续跑不重复 | 构造"已中途固化 + 崩溃"（`turns_consolidated` 设为中途值），续跑后断言长期记忆里没有重复文本 |
| 写入幂等 | 同一 `character_id` 连写两次相同文本，检索结果只有一条 |
| 降级路径同样幂等 | 同上，但在 `_CHROMA_AVAILABLE = False` 的路径上（契约 6 / R2） |
| **既有** `test_resume_after_crash_replays_unconsolidated_turns_into_memory` | 必须继续通过 |

> **测试陷阱**：`tests/test_scene_engine.py` 里多处 `patch(... MemoryManager.consolidate ...)`。
> 改了触发时机后这些 patch 的语义会变，逐个确认断言是否仍成立，
> **不要图省事直接删断言**。另见 `CONVENTIONS.md` §7 的三条"假通过"。

**手工**：把 `max_turns` 调到 50 跑一场，中途 `Ctrl+C` 杀掉进程 → 重启 → 续跑 →
用 `scripts/check_memory_dupes.py` 确认没有新增重复。
