## 怎么复现

三种做法，从便宜到贵。导入不调 LLM，会比对本机配置与 `settings.json` 并列出差异。

**A. 只重跑第 5 场（固定导演脚本，看王冠触发率）**

```bash
python -m scripts.reference_run import --from docs/test-fixtures/reference-runs/2026-11-21-glass-crown --name 复现-第5场 --scene 5
```

新项目里会有一个待开演的场景，照搬记录里第 5 场的描述、参演、在场物件、预制揭示与初始条件；在导演页打开它并开演。
角色**没有前四场的记忆**，只靠场景描述与初始条件里的前情。它回答的问题是：导演脚本相同的前提下，角色会不会去戴、裁决会不会触发。
多导入几次、各跑一遍，才有触发率可言。

**B. 全程重跑（同一起点，导演重新规划）**

```bash
python -m scripts.reference_run import --from docs/test-fixtures/reference-runs/2026-11-21-glass-crown --name 复现-全程
```

在导演页让导演规划第一场、开演，然后打开自动推演。角色卡与物件和这次逐字相同，导演的规划每次不同。导入的项目没有图谱（导演不读图谱，不影响推演）。

**C. 本机从快照分叉（带完整记忆，只在产生这份记录的机器上可用）**

原项目 `35fd1cb8-92e6-476a-a61b-57bf40ece334`，第 5 场的前置快照 `ed49da22-77f8-4847-9e18-3d2af5ec52bc`。
从它分叉得到的首场带着前四场的记忆与世界状态，最接近原现场。

**怎样算复现成功**：第 5 场出现带"幻象"的环境回合（`DialogueTurn.projection` 非空），之后至少有一个其他角色的台词引用了投影里的内容，
并且没有 `failed` 的物件动作。

## 这次成功里的水分

对照时别把下面几条当成已经解决：

1. **王后其实没有戴上。** 第 17 轮是"王冠已举至鬓边"，环境叙述自己写着"尚未触及发丝"，却判了触发。这与设计单里记为误判的"举过头顶就触发"是同一类；
   这次恰好是剧情需要的。导演把触发条件写得很宽（"以试戴、验冠、代持或强夺等任何方式"）也有帮助。
2. **王后去戴冠，是因为导演在场景描述里写了"王后走出最自负的一步，宣布亲自试戴验冠"**，而场景描述会进每个在场角色的 system。
   同一段描述里还写着"伊莎贝尔非亲生、粮荒系王后人为仍属导演视角，不得被任何角色凭空引用"——等于把这两个秘密发给了全体在场角色。
   这次没有角色引用，但那是"知道了、被要求别说"。第 3 场的描述同样写了"赫尔不得知晓粮荒出自王后"，而赫尔在场。
3. **第 2 场像是规划失败后的兜底**：场名"宫廷悬疑四部曲"、地点"未知地点"、描述只有一句、没有物件，AutoPilot 照常往下跑了。
4. **"旋开底座"没有被环境接住**：动作里没出现"王冠"或其别名，被记为 `no_object`，预制的"夹层空空如也"没有触发，是王后自己宣布了查验结果。
5. **两人来回对话仍在**：第 1 场前 11 轮只有塞芙拉与诺安发言。选人调用也是全程最大的开销（约 69.7 万输入 token，角色发言约 28.3 万）。
6. **只有一次。** 这份记录说明这条路走得通，不说明成功率。
